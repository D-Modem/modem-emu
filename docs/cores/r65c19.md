# Rockwell R65C19 / C39 core

File: `modem_emu/cores/r65c19.py`. Tests: `tests/test_r65c19.py`.

## Sources

- Rockwell "R65C19 Microcomputer" data sheet, 1992 (here "DS"). On
  bitsavers: `components/rockwell/R65C19_Data_Sheet_199202.pdf`.
- Rockwell "C29/C39 Technical Reference Manual" (here "TRM"). On
  bitsavers: `components/rockwell/C29_C39_Technical_Reference_Manual.pdf`.
- The MAME core `src/devices/cpu/m6502/r65c19.cpp` and its instruction
  files `dr65c19.lst` and `or65c19.lst` (BSD-3-Clause). We used them only
  to compare the behaviour. We did not copy code from them.

## What the core does

- All 256 opcodes of the R65C19. Table A-3 of the DS and the MAME opcode
  map agree. The opcode map is in `OPCODES`.
- The registers A, X, Y, S, P, PC, and the two new 16-bit registers W
  (multiply and accumulate) and I (threaded code).
- RES ($FFFE), NMI ($FFFC) and IRQ. The board gives the IRQ vector:
  `irq_vector(n)` for the ROM vectors IRQ1-IRQ6 ($FFFA-$FFF0), or a page 1
  RAM vector for the timers (TRM table 3-5).
- BRK uses the NMI vector on the C39 (TRM 3.5.2). For a C29, make the core
  with `brk_vector=0xFFF0`.
- `disasm(read, addr)`: a disassembler with the same opcode map.
- `C39Banks`: the eight Bank Select Registers of the C39 ($0018-$001F) and
  the Port B Select register. `decode(addr)` gives the chip select (ES0 to
  ES4) and the 17-bit external address (TRM 3.8).

## Differences from the 65C02

| Item | 65C02 | R65C19 |
|---|---|---|
| $x1 opcodes | `(zp,X)` | `(zp)` |
| $x1 opcodes, odd rows | `(zp),Y` | `(zp),X` |
| JSR | Pushes the address of the last byte of JSR | Pushes the address of the next opcode |
| RTS | Adds 1 to the address | Does not add 1 |
| $89, $64, $74 | BIT #imm, STZ zp, STZ zp,X | ADD #imm, ADD zp, ADD zp,X |
| $1A, $3A | INC A, DEC A | NEG A, ASR A |
| $04, $0C, $14, $1C, $9C, $9E | TSB, TRB, STZ | NOP, except $0C, which is JPI |
| $CB, $DB | WAI, STP | PHI, PLI |

## New instructions

| Group | Instructions | Notes |
|---|---|---|
| Multiply | MPY, MPA, RND, TAW, TWA, CLW, PHW, PLW | Signed 8 x 8. MPA adds to W with saturation and sets V. Y gets the low byte. |
| Filter | ASR, NEG, LAB, EXC, PSH, PUL, JSB0-JSB7 | JSB n jumps through $FFE0 + 2n. |
| Threaded code | NXT, LII, LAI, LAN, INI, PHI, PLI, PIA, JPI, TIP | JPI puts the operand address in I. TIP returns. |
| Controller | BAR, BAS, RBA, SBA, STI, ADD | See the operand order below. RBA and SBA also load the mask into A (TRM p. C-29). |

Operand order (the same as in the Apex firmware trace,
`txcel-cellular/firmware-trace.md` section 2):

| Instruction | Bytes |
|---|---|
| `RBA #mask, abs` | `C2 mask lo hi` |
| `SBA #mask, abs` | `D2 mask lo hi` |
| `BAR abs, #mask, rel` | `E2 lo hi mask rel` (branch when one or more mask bits are 0) |
| `BAS abs, #mask, rel` | `F2 lo hi mask rel` (branch when one or more mask bits are 1) |
| `STI #imm, zp` | `B2 imm zp` |

## Check on real firmware

The Apex Mobile Plus V.34 firmware 1.601-US boots on the core with a
minimal board (flash on ES3, RAM on ES2, the data pump on ES4). It sets the
C39 registers, loads the BSRs, and then waits in a loop at $4D10 for the
data pump ready code (`$3C` in data pump register 1C, `$EA` in 1D). When a
stub gives these codes, the firmware continues to $4C4F. There it waits
for bit 3 of register 1E. The test `test_apex_boot_reaches_data_pump_handshake`
does the first part. Set `MODEM_EMU_APEX_ROM` to the image to run it.

## Limits

- The cycle counts are the base counts of the DS, with one more cycle for
  a taken branch, a page crossing and a decimal ADC/SBC. They are not exact
  for each bus cycle.
- The core does not have the internal peripherals of the C39 (ports,
  timers, PTGs, the USART, the host UART emulation, CIR). The board model
  must supply them.
- RND follows MAME: the low byte of the rounded value comes from Y. The DS
  text does not give enough detail to confirm this.
