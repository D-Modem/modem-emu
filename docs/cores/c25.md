# TMS320C25 core

File: `modem_emu/cores/c25.py`. Assembler for test programs:
`modem_emu/cores/c25asm.py`.

## Sources

- TI "Second-Generation TMS320 User's Guide", SPRU014, 1987 (here "UG").
  On bitsavers: `components/ti/TMS320xx/3202x/`.
- The MAME core `src/devices/cpu/tms32025/tms32025.cpp` (tag `mame0270`,
  BSD-3-Clause). We used it only to compare the behaviour. We did not copy
  code from it.

## Check against MAME (2026-11-25)

We compared each instruction of the core with the MAME core. These items
were different. Each item now agrees with MAME and with the UG. The tests
are in `tests/test_c25_checks.py`.

| Item | Before | Now |
|---|---|---|
| ADDH | C was set to 0 when there was no carry | A carry sets C. C does not change when there is no carry. |
| SUBH | C was set to 1 when there was no borrow | A borrow sets C to 0. C does not change when there is no borrow. |
| SUBC | OV and C did not change | OV and C change. OVM has no effect. |
| ABS | C did not change | C is set to 0 |
| BNV | OV did not change | BNV sets OV to 0 when it does not branch |
| TBLR, TBLW in a repeat | ACC increased with each word | ACC does not change. An internal address counter increases. |
| RPT | Used the full data word | Uses the low 8 bits |
| LST, LST1, SST, SST1 with indirect addressing | The next-ARP field changed ARP and ARB | The next-ARP field has no effect |
| Hardware stack | A pop of an empty stack gave 0 | 8 fixed levels. A pop copies the bottom word up, as on the chip. |
| CONF (CE3Ch-CE3Fh) | Changed CNF | No effect. CONF is a TMS320C26 instruction. |
| Cycle count | 1 for each instruction | The MAME counts for on-chip memory (refer to the next section) |

## New functions

- **MP/MC pin**: `C25(prog, rom=..., mp_mc=1)`. When `mp_mc` is 1, program
  addresses 0x0000-0x0FFF are external (`pm`). When it is 0, they are the
  4K-word on-chip ROM (`rom`). The UG (section 3.4) says that the pin is
  not latched. Thus a test can change `core.mp_mc` at any time. A write to
  the ROM has no effect.
- **XF pin**: `core.xf_out = fn(level, cycles)`. SXF and RXF call it.
- **Repeat of NOP**: `RPTK n` + `NOP` adds the cycles in one step. This
  makes the delay loops fast.

## Cycle counts

The counts are for on-chip program and data memory with no wait states.
Most instructions take 1 cycle. These take more: TBLR 3; TBLW, MAC, MACD,
BC, BNC, IN, OUT, the two-word D-group instructions (LALK, LRLK, ADLK,
SBLK, ANDK, ORK, XORK) and all branches 2; TRAP, CALA, BACC and RET 2;
IDLE 3. These counts are the same as MAME. They are approximate. For
example, the UG gives more cycles for external memory and for a branch
that is taken. Do not use the core for exact timing of external memory.

## Limits

- The timer, the serial port and the global memory are not in the core.
- The pipeline is not in the core. An instruction that changes CNF has its
  effect at once (on the chip, the next two fetches use the old value).
- The interrupt order is the order of `irq()` calls, not the hardware priority.
